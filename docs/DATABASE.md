# Database

Postgres on Supabase. All changes are SQL migrations in `supabase/migrations/` (applied in
filename order by `supabase db reset` locally and `supabase db push` remotely).

| Migration | Purpose |
|---|---|
| `…0001_core_schema.sql` | tables, triggers, `is_admin()`, `rate_limit_hit()` |
| `…0002_rls_and_grants.sql` | deny-by-default grants, RLS policies, private `media` bucket |
| `…0003_business_functions.sql` | `fulfil_order`, `apply_refund`, `publish_site`, `record_view` |
| `…0004_seed_scrapbook_template.sql` | template `scrapbook` v1 + the V1 product (generated by `scripts/gen-template-migration.ts`) |
| `…0005_admin_content_isolation.sql` | content tables readable by owners only |
| `…0006_anon_is_admin.sql` | lets anonymous visitors evaluate the public catalog policy |

## Tables

| Table | Key columns | Notes |
|---|---|---|
| `profiles` | `id` = auth user, `email`, `role` (`customer`/`admin`) | created by trigger on sign-up |
| `templates` | `key`, `is_active` | public catalog |
| `template_versions` | (`template_key`, `version`), `schema_version`, `default_content`, `is_current` | one current version per template |
| `products` | `price_paise`, `edit_days` (30), `live_days` (365), `is_active` | public catalog; price edited in admin |
| `orders` | `user_id` (null after account deletion), `amount_paise`, `status`, `receipt`, `razorpay_order_id` | `created → paid → refund_pending → refunded`, or `expired` |
| `payments` | `razorpay_payment_id` (unique), `status`, `is_duplicate`, `refund_status`, `refunded_paise` | one row per payment attempt |
| `payment_events` | `event_id` (unique), `event_type`, `summary` (PII-free), `processed_at`, `attempts` | webhook inbox / idempotency |
| `sites` | `user_id`, `order_id` (unique), `status`, `slug` (unique, 22 base62), `passcode_hash`, `draft_content`, `draft_revision`, `published_version_id`, `edit_until`, `expires_at`, `view_count` | `draft → published ⇄ unpublished`, `disabled`, `expired`, `deleted` |
| `site_versions` | `site_id`, `version`, `content`, `schema_version` | immutable published snapshots |
| `assets` | `site_id`, `user_id`, `kind`, `status`, `storage_prefix` (= id), `variants`, `rights_confirmed_at` | `pending → ready` or `rejected`; trigger: owner must own the site |
| `audit_log` | `actor_id`, `actor_role`, `action`, `target_type/id`, `meta` | admin + business events |
| `abuse_reports` | `site_id`, `reason`, `details`, `reporter_hash`, `status` | from the renderer's report link |
| `rate_limits` | (`key`, `window_start`), `count` | keys are keyed hashes; cleaned daily |

Money is integer paise. Content JSON is size-capped at 256 KB.

## Access rules (summary)

- `anon`: `SELECT` active `templates`/`products` only.
- `authenticated`: `SELECT` own `profiles`, `orders`, `payments` (via order), `sites`,
  `site_versions`, `assets`; admin tables return rows only when `is_admin()` (role admin **and**
  JWT `aal = aal2`) — and never the content tables. No write grants at all.
- `service_role`: everything (server only).

## Functions

- `fulfil_order(order, payment, amount, currency, method, actor)` — locks the order; returns
  `fulfilled` (creates the site from the template's default content, sets edit/live windows),
  `already`, `duplicate` (records an extra payment for auto-refund), `amount_mismatch` or
  `unknown_order`.
- `apply_refund(payment, refund, amount, status)` — pending/processed/failed; a full refund of the
  real payment marks the order refunded and disables the site.
- `publish_site(site, user, content, schema_version, new_slug)` — owner + status + edit window
  checks, writes the next `site_versions` row, keeps an existing slug.
- `record_view(site)`, `rate_limit_hit(key, window, max)`.

## Types

`npm run db:types` regenerates `src/lib/supabase/database.types.ts` from the local database.

## Backups

Supabase Pro takes daily database backups (enable PITR when revenue justifies it). Storage objects
are **not** in those backups — `scripts/backup-storage.ts` copies them nightly to an S3-compatible
bucket (see DEPLOYMENT.md). Restore drill: DEPLOYMENT.md → Runbooks.
